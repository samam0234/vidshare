## 1. 요청

쇼츠를 올린 뒤 **삭제하거나 수정할 수 없다.** 카드 왼쪽 위에 점 3개(세로) 설정 버튼을 두고,

- 업로더: 수정 · 각종 조정 · 삭제
- 다른 유저·비로그인: **비추천**을 누르면 그 영상이 알고리즘(추천)에서 제외, 그 밖에 필요한 기능

## 2. 해석과 결정

| 요청 | 결정 |
|------|------|
| "각 조정 기능" | 수정(제목·설명·썸네일) 외에 **공개 범위(공개/비공개)** 와 **댓글 허용(켜기/끄기)** 으로 해석 |
| "알고리즘에서 제외" | 이 프로젝트에는 점수 기반 추천이 없고 최신순 피드다. 그래서 **그 시청자의 피드에서 영상을 뺀다**로 구현. 전체 노출을 깎는 방식(비추천 N개면 모두에게서 제외)은 **하지 않았다** — 계정 없이 누를 수 있는 버튼이라 한 명이 남의 영상을 묻는 데 쓸 수 있다 |
| 비로그인 비추천 | 계정이 없으므로 이 브라우저의 localStorage 에 저장(최대 300개). 로그인 유저는 서버에 저장되어 기기를 바꿔도 이어진다 |
| 그 밖의 기능 | 링크 복사(모두), 작성자 프로필(모두), 신고(로그인), 작성자 차단(로그인) — 비로그인이 신고·차단을 누르면 로그인 화면으로 |
| 영상 파일 교체 | 하지 않았다. 좋아요·댓글이 붙은 영상의 내용을 바꾸는 일이라 별도 설계가 필요 |

## 3. 변경

### 백엔드

| 파일 | 내용 |
|------|------|
| `db/migrations/0002_short_controls.ts` | `shorts.visibility`(`public`/`private`, CHECK), `shorts.comments_enabled`(0/1), 테이블 `short_dislikes(user_id, short_id)` — **23개 테이블** |
| `data/store.ts` | `updateShort`·`deleteShort`(소유 확인), `dislikeShort`·`undislikeShort`, `getShortAccess`, 공개 범위 필터(`visibleClause`), 추천 피드의 비추천 제외(`excludeDisliked`), 업로드 파일 정리(`removeUploadIfUnreferenced`) |
| `routes/shorts.ts` | `PATCH /:id` · `DELETE /:id` · `POST/DELETE /:id/dislike`. 제목 100자·설명 2000자 상한(생성에도 적용) |
| `routes/comments.ts` · `search.ts` · `playlists.ts` · `users.ts` | 남의 비공개 쇼츠는 읽기·쓰기·검색·재생목록·프로필에서 404/제외, 댓글을 닫은 영상은 새 댓글 403 |
| `routes/admin/content.ts` | `GET /api/admin/content/shorts` — **비공개를 포함한 전체 목록**(운영자 전용). 콘솔이 공개 `/api/shorts` 를 쓰고 있어, 이게 없으면 신고된 영상을 비공개로 돌려 검토를 피할 수 있었다. 콘솔(`adminApi.getShorts`)이 이 경로를 쓰고 비공개 표시를 붙인다 |
| `upload/files.ts` | `deleteStoredUpload` — `/uploads/<uuid>.<ext>` 형태만, uploads 폴더 안으로 한정 |

비추천은 **추천 피드(검색어 없는 `GET /api/shorts`)와 팔로잉 피드**에만 적용한다. 검색·프로필·직접 링크는 그대로.

## 5. 알려진 한계

- 비로그인 비추천은 브라우저·기기를 바꾸면 이어지지 않는다.
- 로그인 유저의 비추천 목록을 모아 보거나 한꺼번에 푸는 화면이 없다(지금은 안내창의 "되돌리기"뿐).
- 쇼츠 영상 파일 자체는 교체할 수 없다.
- 롱폼·커뮤니티 삭제는 여전히 업로드 파일을 남긴다.
- 비추천 수는 전체 노출에 반영하지 않는다(위 2장).
