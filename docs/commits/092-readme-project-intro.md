## 2. 개요

### 배경

포트폴리오로 제출할 준비를 하며 저장소를 처음 여는 사람 관점에서 README를 다시 읽었다.
첫 화면이 `cd BackendServer && npm install` 로 시작해서, **이 프로젝트가 무엇이고
무엇을 구현했는지**가 스크롤을 내려야 나왔다. 리뷰어는 대개 그 전에 창을 닫는다.

두 번째 문제는 문서 간 수치 불일치다. SQLite 테이블 수가
`overview.md` 안에서만 19개(다이어그램) / 18개(디렉터리 트리) / 17개(표 제목)로
세 번 다르게 적혀 있었고, `roadmap.md` 는 18개였다. 실제 `schema.ts` 의
`CREATE TABLE` 은 22개다. 숫자가 틀린 문서는 나머지 서술의 신뢰도까지 깎는다.

### 목표

- README 상단만 읽고도 프로젝트의 정체·규모·기술 선택을 파악할 수 있게 한다
- 문서에 적힌 정량 수치를 코드와 일치시킨다

### 범위 (In Scope)

- README 소개·주요 기능·기술 스택·시스템 구성 섹션 신설
- 배지, 배포 링크, 포트폴리오 폴더 링크
- SQLite 테이블 개수 정정 (4곳)
- `현재 상태` 표에 미완 항목 행 추가

### 범위 밖 (Out of Scope)

## 4. 기타

### 검증 방법

```bash
# 테이블 개수 실측
grep -c "CREATE TABLE" BackendServer/src/db/schema.ts   # 22

# 문서에 남은 옛 수치가 없는지
grep -rn "17개 테이블\|18개 테이블\|19개 테이블" docs/ README.md   # 결과 없음
```

### 트레이드오프 · 결정 이유

- **기술 스택 표에서 `zod` 를 뺐다.** `package.json` 에는 있지만
  `BackendServer/src` 안에서 한 번도 import 되지 않는다. 쓰지 않는 의존성을
  스택으로 내세우는 것은 이력서의 과장과 같다. 입력 검증은
  [security-notes.md](../security/security-notes.md) 4장에 여전히 미완으로 남겨 둔다.
- **Express 버전을 5가 아닌 4로 적었다.** 설치된 것은 `^4.21.2` 다.
- **배포 링크에 단서를 달았다.** Workers 에 올라간 프론트는 공개 백엔드가
  붙기 전까지 UI 확인용이다. 링크만 걸고 "동작한다"고 두면 리뷰어가 눌러 보고
  기능이 죽어 있다고 판단한다.

### 리스크 · 알려진 이슈

- 배지는 shields.io 외부 이미지다. 오프라인·사내망에서는 깨져 보인다.
- 테이블 개수는 스키마가 늘면 또 어긋난다. 자동 검증은 없다.
