# 보안 포인트

**상태**: 현재 프론트 데모 기준  
**최종 갱신**: 2026-08-14

이 문서는 **지금 당장 위험한 것**과 **백엔드 도입 시 반드시 지킬 것**을 구분합니다.

---

## 1. 현재 데모에서의 현실

| 항목 | 상태 | 설명 |
|------|------|------|
| 인증 | 없음 | 누구나 UI만 사용, 권한 개념 없음 |
| 데이터 영속 | 없음 | mock + 메모리 상태 |
| 비밀키 | 없음 | 환경 변수 기반 시크릿 미사용 |
| XSS 표면 | 낮~중 | React 기본 이스케이프 의존, `dangerouslySetInnerHTML` 미사용 |
| CSRF | N/A | 변경 API 없음 |
| 업로드 | 클라이언트 미리보기만 | 서버로 파일 전송 없음 |

**결론**: 데모 자체는 네트워크 공격 표면이 작지만, **프로덕션으로 오인하고 배포·실데이터 연동하면 위험**합니다.

---

## 2. 프론트에서 이미 신경 쓴 점

- 사용자 입력 댓글/메시지를 **텍스트 노드**로 렌더 (HTML 삽입 금지)
- 외부 샘플 영상 URL은 고정 목록 (임의 URL 주입 UI 없음)
- 테마 등 민감 정보 아닌 값만 `localStorage` 사용

---

## 3. 알려진 한계·주의

1. **클라이언트 상태 = 신뢰 불가**  
   좋아요 수, 댓글 작성자명 등은 브라우저에서 조작 가능. 서버 검증 필수.
2. **sample 영상 URL**  
   외부 호스트 의존. CSP·혼합 콘텐츠 정책 배포 시 검토.
3. **로그인 버튼 UI만 존재**  
   실제 세션 없음 → “로그인한 것처럼” 보이는 UI를 보안 경계로 쓰지 말 것.
4. **파일 input 미리보기**  
   큰 이미지 data URL은 메모리 부담. 추후 크기·타입 검증 필요.

## 4. 백엔드 도입 시 체크리스트

### 인증·세션
- [ ] 비밀번호 해시 (bcrypt/argon2 등)
- [ ] 세션 쿠키 `HttpOnly`, `Secure`, `SameSite`
- [ ] 로그아웃·세션 무효화
- [ ] 무차별 대입 방지 (rate limit)

### API
- [ ] 모든 쓰기 API 인증 필수
- [ ] 리소스 소유권 검사 (내 영상만 삭제 등)
- [ ] 입력 검증·스키마 (zod 등)
- [ ] Rate limiting

### 업로드
- [ ] 허용 MIME/확장자 화이트리스트
- [ ] 최대 용량 제한
- [ ] 바이러스/악성 콘텐츠 스캔 (가능 시)
- [ ] 저장 경로 추측 불가 (랜덤 키), 직접 실행 금지
- [ ] 가능하면 전용 object storage + 서명 URL

### 웹 보안 헤더
- [ ] CSP
- [ ] `X-Content-Type-Options`, `Referrer-Policy` 등
- [ ] HTTPS only

### 비밀 관리
- [ ] `.env` 를 git에 커밋하지 않음 (`.gitignore` 유지)
- [ ] 프로덕션 시크릿은 호스트/시크릿 매니저

### 개인정보
- [ ] 최소 수집
- [ ] 로그에 토큰·비밀번호 금지
- [ ] 삭제·내보내기 요구 대응 계획
