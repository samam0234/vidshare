# 보안 포인트

**상태**: Front + Backend 데모 기준  
**최종 갱신**: 2026-10-02

이 문서는 **지금 당장 위험한 것**과 **백엔드 도입 시 반드시 지킬 것**을 구분합니다.

---

## 1. 현재 데모에서의 현실

| 항목 | 상태 | 설명 |
|------|------|------|
| 인증 | bcrypt + HttpOnly 세션 | 쓰기 API는 `requireRequestUser()` |
| 데이터 영속 | PostgreSQL 16 | 앱 전용 계정 `vidshare` (슈퍼유저 아님). 로컬 D 드라이브 · 운영 VM 부트 디스크(localhost 전용) |
| 비밀키 | 환경 변수 | LLM 키는 `.env` (git 무시) |
| XSS 표면 | 낮~중 | React 기본 이스케이프 의존, `dangerouslySetInnerHTML` 미사용 |
| CSRF | 세션 쿠키 | 기본 `SameSite=Lax`. **운영은 `SameSite=None`**(프론트·API 가 다른 사이트) — 5-2 참고 |
| 업로드 | 로컬 디스크 | 로그인 필요, MIME 화이트리스트, 용량 제한, UUID 파일명 |

**결론**: 데모 자체는 네트워크 공격 표면이 작지만, **프로덕션으로 오인하고 배포·실데이터 연동하면 위험**합니다.

## 2. 프론트에서 이미 신경 쓴 점

- 사용자 입력 댓글/메시지를 **텍스트 노드**로 렌더 (HTML 삽입 금지)
- 외부 샘플 영상 URL은 고정 목록 (임의 URL 주입 UI 없음)
- 테마 등 민감 정보 아닌 값만 `localStorage` 사용

## 3. 알려진 한계·주의

1. **클라이언트 상태 = 신뢰 불가**  
   좋아요 수, 댓글 작성자명 등은 브라우저에서 조작 가능. 서버 검증 필수.
2. **sample 영상 URL**  
   외부 호스트 의존. CSP·혼합 콘텐츠 정책 배포 시 검토.
3. **법적 고지**  
   `/privacy` 에 수집 항목을 적어 두었다. 사업자등록 전이라 `/business` 번호는 미등록이다.
4. **업로드 파일은 정적 공개**  
   `GET /uploads/:file` 는 인증 없이 재생된다. URL을 알면 누구나 받는다. 비공개 영상은 미구현.
5. **data URL 거부**  
   생성 API는 `data:` 를 거절한다. 기존 DB에 남은 data URL 썸네일은 읽기만 된다.

## 5-1. 관리자 콘솔 (081~084)

**설계상 지킨 것**

- 관리자 세션 쿠키를 사용자 세션과 **이름부터 분리** (`vidshare_admin_sid`).
  일반 로그인으로 관리자 라우트를 탈 수 없다.
- `requireAdmin` 실패는 비로그인·일반 유저·정지된 관리자를 구분하지 않고 **동일한
  401**. 관리자 로그인 실패 메시지도 하나로 통일 — 핸들을 넣어 보며 "이 계정이
  관리자인가"를 떠보지 못하게.
- 관리자 계정은 **시드에 없다.** `npm run create-admin` 으로 각 환경에서 직접 만든다
  (비밀번호가 소스·저장소에 남지 않음).
- 비밀번호를 잊으면 `npm run reset-password -- <handle>` 로 **재설정만** 된다(해시는 되돌릴 수 없음).
  재설정과 그 계정의 세션 삭제는 한 트랜잭션. 웹에는 재설정 경로가 없다 — 서버 SSH 키가 곧 본인 확인(104).
- 관리자가 자기 자신이나 다른 관리자를 정지시키는 것은 400으로 차단 — 콘솔에
  아무도 못 들어가는 상태를 막는다.
- 유저를 정지하면 그 유저의 `sessions` 행을 즉시 전부 삭제하고, 재로그인은 403.
- 콘솔 페이지는 `robots: index:false`.

**남아 있는 위험**

- **관리자 조치 감사 로그가 없다.** 누가 무엇을 지웠는지 추적할 수 없다.
- 관리자 계정에 2FA·IP 제한이 없다. 비밀번호 하나가 전부다 — 운영 배포 시에는
  콘솔을 VPN·IP 허용 목록 뒤에 두는 것을 권장한다.
- `--promote` 로 승격한 계정은 **기존 비밀번호를 그대로 쓴다.** 일반 유저로
  쓰던 계정을 올릴 때는 비밀번호를 먼저 바꿀 것.
- 관리자 목록 API에 페이지네이션이 없어 전량이 한 번에 응답에 실린다.

## 5-1b. 쇼츠 공개 범위 · 비추천 (107)

- **비공개**(`shorts.visibility = 'private'`)는 작성자에게만 보인다. 목록·상세·프로필·검색·팔로잉 피드·재생목록 항목은 물론,
  댓글 읽기·쓰기·좋아요·재생목록 담기·비추천도 남에게는 **없는 영상(404)** 으로 취급한다(존재 여부를 알려 주지 않는다).
- **작성자만** 수정·삭제할 수 있다. 다른 유저는 403, 비로그인은 401. 소유 확인은 세션의 유저 id 로만 한다.
- **비추천**은 *그 시청자의 추천 피드*에서만 영상을 뺀다. 영상 자체·다른 시청자의 피드는 그대로다 — 계정 없이 누를 수 있는
  버튼이 다른 사람의 영상을 지우거나 묻는 수단이 되지 않게 하려는 의도다. 로그인 유저는 서버(`short_dislikes`), 비로그인은
  이 브라우저의 localStorage(`vidshare:hidden-shorts`, 최대 300개)에만 저장한다.
- **운영자는 비공개도 본다.** 콘솔은 `GET /api/admin/content/shorts`(관리자 세션 필요)로 전체 목록을 받는다. 공개 `/api/shorts` 를 쓰면
  신고된 영상을 비공개로 돌려 검토를 피할 수 있기 때문이다.
- 신고·차단은 기존대로 로그인이 필요하다(비로그인은 로그인 화면으로 안내).

## 5-2. 현재 운영 구성의 쿠키 · CORS (103)

- 프론트(`*.workers.dev`)와 API(`*.trycloudflare.com`)가 다른 사이트라 **운영 쿠키는 `SameSite=None; Secure`** 다.
  다른 사이트에서 오는 요청에도 쿠키가 실리므로, 방어는 **CORS 화이트리스트**(`CORS_ORIGIN` 두 오리진만,
  `credentials` 허용)와 JSON 요청 본문에 기댄다. 도메인을 마련해 `SameSite=Lax` 로 되돌리는 것이 정식 해법이다
  ([배포 가이드 3장](../deployment.md)).
- 서드파티 쿠키를 막는 브라우저(Safari 기본)에서는 로그인이 안 될 수 있다 — 보안 문제는 아니고 가용성 문제.
- **CORS 가 사설망 호스트를 전부 허용**한다(`isDevAllowedOrigin`). 프로덕션에서는
  `CORS_ORIGIN` 을 반드시 명시할 것.
- 업로드 파일 삭제는 **쇼츠만** 정리된다(107). 작성자·관리자가 쇼츠를 지우거나 썸네일을 바꾸면, 다른 쇼츠·롱폼이 같은 파일을
  쓰지 않는 경우에 한해 디스크에서도 지운다(`/uploads/<uuid>.<ext>` 형태만, 외부 URL 은 건드리지 않음). 롱폼·커뮤니티 삭제는 아직 파일이 남는다.

## 5-3. Oracle Cloud · PostgreSQL 운영 (097)

**현재 운영(전용 VM + 터널, 103)에서 적용된 것**

- 인바운드는 **22 만** 열려 있다(OCI 보안 목록 + iptables). 공개 트래픽은 `cloudflared` 가 바깥으로 연 터널로만 들어온다.
- Node 는 `0.0.0.0:4000` 에 바인드하지만 4000 은 바깥에서 닿지 않는다. Postgres 는 localhost 전용.
- 블록 볼륨이 없어 `RequiresMountsFor` 는 빼고 설치한다. 외부 백업은 이 PC 의 D 드라이브 사본뿐이다.

**`setup-vm.sh`(Caddy 구성)가 기본으로 적용하는 것**

- Postgres 는 `listen_addresses = 'localhost'` — 5432 를 인터넷에 열지 않는다.
  OCI 보안 목록도 80·443(+ 내 IP 의 22)만 연다.
- 앱은 슈퍼유저가 아닌 `vidshare` 계정으로 접속한다. 비밀번호는 `/etc/vidshare/backend.env` (600) 에만.
- Caddy 가 HTTPS 를 끝내고, Node 는 `127.0.0.1:4000` 에서만 받는다(`TRUST_PROXY=1`).
- systemd 유닛은 `NoNewPrivileges`, `ProtectSystem=full`, 블록 볼륨 마운트를 요구(`RequiresMountsFor`).
- 백업 파일은 `root:adm 640` — 웹 경로(`/uploads`)와 분리.

**직접 해야 하는 것**

- [ ] SSH 키 인증만, 비밀번호 로그인·루트 로그인 끄기 (`/etc/ssh/sshd_config`)
- [ ] OCI 보안 목록에서 22 를 **내 IP 만** 허용
- [ ] 운영 DB 에 시드 계정(`demo` / `demo1234`)이 생겼다면 정지하거나 삭제 — 비밀번호가 공개되어 있다
- [ ] 외부에서 `nmap -p 4000,5432 <IP>` 로 닫혀 있는지 확인
- [ ] 백업 복원 연습 (분기 1회, [docs/ops/backup-restore.md](../ops/backup-restore.md))

**내 PC(D 드라이브) 쪽 주의**

- 설치된 Postgres 의 `listen_addresses = '*'` 이지만 `pg_hba.conf` 가 127.0.0.1/::1 만 허용한다.
  공유기 포트포워딩을 열지 않는 한 외부 접속은 불가하다. 굳이 열어 둘 이유가 없다면 `localhost` 로 줄이는 편이 안전하다.
